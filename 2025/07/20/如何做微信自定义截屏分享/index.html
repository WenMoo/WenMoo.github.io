如何做微信自定义截屏分享

Author: WenMo Date: July 20, 2025  23:20:49

我们游戏中也往往需要做截图分享，或者截图保持到本地等功能，这里就以微信小游戏平台为例，其他平台基本大同小异，原理上共通，可能API不同罢了。

获取像素

这段代码当时我有几个疑问：

  • 为什么要创建一个相机，不创建不行吗？应为单纯看到相机赋值，没看到相机做了什么
  • 为什么要延迟一帧才去获取？

第一个问题：

要做截图，我们首先需要拿到需要的渲染数据，我们新建了一个纹理对象 rt，同时我们有一个相机，那么问题来了，为什么我们需要这个相机，我们直接创建了这个纹理对象后，直接把 this.rt.readPixels把纹理写入不就好了吗？

但实际上是不可以的!RenderTexture 本身只是一个 空的可写纹理对象。它 不会自动包含任何画面内容，它 不能手动写入像素，不能自己渲染，必须由 Camera 渲染 才会有图像。所以不绑定相机，让相机把场景写到这张纹理上，它里面就什么都没有。

在 WebGL / OpenGL 层面 RenderTexture 是：

  • 一个 GPU FrameBuffer
  • 不能 CPU 直接写入（除非通过 glTexSubImage2D 等低层 API，但 Cocos 没暴露）

第二个问题：

因为 Camera 的渲染是异步的 ，设置好的 camera.targetTexture = rt 后 不会立即渲染到 RenderTexture，而是在 下一帧的渲染循环里 才会真正把画面绘制进去。

所以如果 不等待一帧 就 readPixels：

  • RenderTexture 内容尚未更新
  • 得到的像素是空的 / 上一帧的内容 / 残影
  • 有时甚至返回 null 或随机数据

PS： 不同平台上的性能或者手机的渲染延迟可能会更高，Camera 渲染到 RenderTexture 的时序更慢，可以根据实际情况所需来适当增加延迟时间

补充：

在上面我们还看到有一个 CutNode 是用来获取截取的位置和大小的，需要注意的一点是，这个节点的锚点必须是(0,0)，也就是说是左下角，而不是居中的！这是因为 OpenGL 的 readPixels 是从 左下角 开始，而 Canvas 是从** 左上角 **开始。

写入像素

在上面拿到截取区域的 ArrayBufferView 了，我们创建一个 canvas 来保存图片，这里有个问题：

  • 为什么需要创建一个 canvas 才能保存图片？

那是因为小游戏平台（微信，抖音，web等）不能直接将 ArrayBuffer 或 Uint8Array 保存成图片！只接受 Canvas 作为转图片的入口，你不能直接用像素数组创建图片文件。

  • 然后将像素数据写入到这个 canvas 中，需要注意的事，这里代码做了倒序写入 var sRow = params.height - 1 - row 这也是 OpenGL 的 readPixels 是从 左下角 开始，而 Canvas 是从 左上角开始 导致的，不倒序图片就会上下颠倒
  • 然后我们根据平台使用平台提供的API来将canvas转化为临时文件（PNG，JPG等），保持到本地或者分享给好友。

所以说在获取像素这一步，需要注意的一点是坐标问题，以及渲染的异步，而写入数据这步，最关键的是 canvas 作为 “中间桥梁” ，来挂载 ArrayBufferView 的数据，而后根据平台API 来转为图片文件等格式

优化表现

这个功能，我们可以再浪漫餐厅中看到过，他们的效果基本如上面描述，场景是卡牌分享，当玩家需要将指定卡牌分享给别的玩家，那么就希望分享链接的分享图能够是这张卡牌，另外比如一些还希望图片上能自定义内容，比如图片上能加上自定义的文本信息等。

能看到分享的时候会突然闪过一下要分享的图片，这是因为其实上诉做法是当前视图显示出这个 Node，然后截取这一刻的像素信息，然后写入到 canvas 中，再来做转化为图片分享。这个闪一下虽然问题也不大但是就是有那么一丝不完美其实这里我们是能对其进行优化的！解决这个闪一下的问题。

解决的思路是新建一个截图层级，实际上我们是不需要看到这个 Node ，那么我们其实新的需要截取的节点，设置到新的层级，比如 UI_SNAPSHOT 这样，然后我们原本用作截取的 Camera 读取这一层，因为我们不同于我们原本看到 UI 的 Camera ，所以不会被看到，这样也就没有闪一下的表现了，也能完美的获取到像素数据。

小结

虽然标题说的是微信，但其实该实现对于其他渠道，或者不同引擎来说，本质原理都是一样，区别在于 API 的不同罢了
